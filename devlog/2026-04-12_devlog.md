### 일괄 처리 최적화

#### Prisma Transaction 활용
```typescript
await prisma.$transaction(async (tx) => {
  // 1. 기존 출근 기록 삭제 (날짜 중복 방지)
  await tx.attendance.deleteMany({
    where: { workerId, date: { in: dates } }
  });

  // 2. 새 출근 기록 일괄 등록
  await tx.attendance.createMany({ data: attendanceRecords });

  // 3. 급여 재계산 트리거
  await tx.payroll.update({
    where: { workerId, year, month },
    data: { needsRecalculation: true }
  });
});
```

## 💡 오늘의 학습 포인트

### 1. Excel 처리의 두 가지 접근법
- **Server-side (Node.js)**: `xlsx` 라이브러리 사용
  - 장점: 대용량 처리 가능, 보안
  - 단점: 메모리 사용량 증가, API 응답 시간 증가

- **Client-side (Browser)**: `xlsx` 브라우저 번들
  - 장점: 서버 부하 없음, 즉각적인 피드백
  - 단점: 대용량 파일 처리 제한, 보안 취약

**선택**: Server-side 우선, 클라이언트는 미리보기만

### 2. Prisma Transaction의 중요성
일괄 처리 시 트랜잭션을 사용하지 않으면:
- 중간 실패 시 부분 등록 발생
- 데이터 정합성 문제
- 롤백 불가능

```typescript
// ❌ 나쁜 예
for (const record of records) {
  await prisma.attendance.create({ data: record });
}

// ✅ 좋은 예
await prisma.$transaction(
  records.map(record =>
    prisma.attendance.create({ data: record })
  )
);
```

### 3. API 설계 원칙
- **단일 책임**: 하나의 엔드포인트는 하나의 역할만
- **RESTful 네이밍**: `/api/resource/[id]/action` 패턴
- **일관된 응답 형식**: `{ data, error, message }` 구조
- **에러 핸들링**: try-catch + 명확한 HTTP 상태 코드
